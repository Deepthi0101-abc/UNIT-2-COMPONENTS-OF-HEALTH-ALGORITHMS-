Data quality, standards and privacy

Good data is accurate, complete, consistent, timely and valid. Poor data causes wrong results ("garbage in, garbage out"), unsafe decisions (5.5 mmol/L typed as 5.5 mg/dL looks dangerously low), hidden bias and loss of clinician trust.

StandardPurpose
HL7, FHIRExchanging health data between systems
DICOMFormat for medical images
ICDCodes for diseases and diagnoses
SNOMED CTDetailed clinical terms
LOINCCodes for lab tests and observations

Privacy: take patient consent, store data securely, allow access only to those who need it, and anonymise (remove names and identifiers). In India, the Digital Personal Data Protection Act, 2023 and the Ayushman Bharat Digital Mission (ABDM) framework guide how health data is handled.

In depth: what a FHIR record looks like, and sampling bias In depth

FHIR stores each fact as a small structured "resource". A heart-rate reading is an Observation that points to a Patient and carries a standard code, so every system reads it the same way.

{
  "resourceType": "Observation",
  "status": "final",
  "code": { "coding": [{ "system": "http://loinc.org",
            "code": "8867-4", "display": "Heart rate" }] },
  "subject": { "reference": "Patient/123" },
  "valueQuantity": { "value": 78, "unit": "beats/minute" }
}

Data also carries sampling bias. Wearable data comes only from people who can afford a device, and a tertiary-hospital EHR holds sicker patients than the general population. An algorithm trained on such data may work poorly on people who were missing from it. Always ask: who is not in this dataset?

2.2 Data preprocessing

Raw health data has duplicates, errors, gaps, mixed units and mixed formats. Data preprocessing cleans and prepares it so an algorithm can use it. Standard order: remove duplicates, fix errors, handle missing values, check outliers, make units and formats uniform, encode categories, scale numbers.

Missing values

Options: delete the record (simple, but loses data); impute (fill in) with the mean for evenly spread numbers, the median when there are extreme values, or the mode for categories; carry the previous reading forward for time-series; predict the value with a model; or add a "was missing" flag. In healthcare a gap can mean something: a test not ordered may mean the doctor was not worried.

Example: BP readings 120, 130, missing, 140. Mean of known values = 390 ÷ 3 = 130. Length of stay 2, 3, 3, 4, 30 days: mean = 8.4, median = 3, so the median describes a typical patient better.

In depth: why values go missing In depth

PatternMeaningExample
Missing completely at random (MCAR)Gap unrelated to anythingDevice battery died
Missing at random (MAR)Gap depends on another recorded valueOlder patients skip the online survey
Missing not at random (MNAR)Gap depends on the missing value itselfVery ill patients too unwell to give a reading

Simple mean filling is safest under MCAR. Under MAR and MNAR it can bias results, so better methods are used: filling from the most similar patients (k-nearest neighbours) or repeated model-based filling (multiple imputation). Whichever you use, keep a "was missing" flag.

Outliers

An outlier is a value far from the rest. First decide whether it is an error (age 150: correct or remove) or a real extreme (a critically ill patient: keep). Never delete blindly: sicker patients have more extreme values, so deleting them makes the data look healthier than reality.

In depth: the IQR rule In depth Sort the values; Q1 is the median of the lower half, Q3 the median of the upper half, IQR = Q3 − Q1. A value below Q1 − 1.5×IQR or above Q3 + 1.5×IQR is flagged. Example heart rates 60, 64, 68, 70, 72, 74, 76, 78, 80, 200: Q1 = 68, Q3 = 78, IQR = 10, fences 53 and 93, so 200 is flagged. Flagging only means "look at this"; a clinician decides.

Scaling and encoding

Min-max scaling: (value − min) ÷ (max − min), giving 0 to 1. Ages 20 to 80, age 50 → 30 ÷ 60 = 0.5. Standardisation (z-score): (value − mean) ÷ standard deviation. Mean 100, SD 20, value 140 → z = 2.

Encoding: label encoding gives each category a number (Male = 0, Female = 1) and suits categories with a real order; one-hot encoding makes a 0/1 column per category (blood groups A, B, O, AB become four columns) so the algorithm does not think AB is "bigger" than A.

In depth: In depth Skewed values such as length of stay are often log-transformed first. Fit the scaler on the training data only, then apply it to test data; using the whole dataset leaks test information into training.

Integration and standardisation

When data comes from several systems, make units, codes and date formats the same. Glucose: mmol/L × about 18 = mg/dL (6.0 mmol/L ≈ 108 mg/dL). Use standard codes (ICD, LOINC, SNOMED CT) so the same test or disease has one name everywhere. Merge records of the same patient and remove duplicates.

2.3 Feature selection and feature engineering

A feature is one input variable (age, blood pressure, HbA1c). The outcome to predict is the target or label. Features are numerical (weight) or categorical (blood group).

Feature selection

Choosing the useful features and leaving out the rest. It removes noise, speeds up the model, reduces overfitting (learning the data by heart) and makes the result easier to explain.

MethodIdea
FilterScore each feature by its link with the outcome (for example correlation) and keep the best
WrapperTry different groups of features and keep the group that works best
EmbeddedThe algorithm picks features while learning (for example a decision tree)
Expert knowledgeDoctors say which variables matter clinically; always used

Multicollinearity: two features carrying nearly the same information (weight and BMI). Keep the more useful one.

Feature engineering

Creating new, more useful features from raw data: calculation (BMI = kg ÷ m²; pulse pressure = systolic − diastolic), grouping (age group, BMI category), counting (visits in the last year), time (average heart rate over 24 hours, days since last admission) and text (note says "chest pain" → yes/no column).

Data leakage

Data leakage means using a feature that would not be known at the time of prediction. Example: using the discharge diagnosis to predict admission. The model looks excellent in testing and fails in real use. Ask: would I know this value when the prediction is made?

Worked example

Predict diabetes from: age, height, weight, fasting glucose, HbA1c, patient ID, phone number, address. Drop ID, phone and address (no medical value). Create BMI from height and weight. Final features: age, BMI, fasting glucose, HbA1c.

In depth: correlation, elimination and PCA In depth

Correlation (r) runs from −1 to +1. Near +1: both rise together; near −1: one rises as the other falls; near 0: no straight-line link. Correlation is not causation: ice-cream sales and drowning both rise in summer. Recursive feature elimination trains a model, drops the weakest feature, and repeats. L1 (lasso) regularisation is an embedded method that shrinks unhelpful feature weights to zero. PCA combines many correlated features into a few new ones; it reduces size but the new features are harder to explain to a clinician. The curse of dimensionality means that with many features and few patients, a model finds false patterns; select features before adding more.

Quick revision

  • Sources: EHR, LIS, PACS, wearables, surveys, claims, registries. Types: structured, unstructured, imaging, time-series, genomic.
  • Quality: accurate, complete, consistent, timely, valid. Standards: HL7, FHIR, DICOM, ICD, SNOMED CT, LOINC.
  • Preprocessing: clean, handle missing values, check outliers, standardise, encode, scale.
  • Mean for even data, median with extremes, mode for categories. Min-max = (x − min) ÷ (max − min); z = (x − mean) ÷ SD.
  • Selection chooses features, engineering creates them. Avoid leakage and multicollinearity.
